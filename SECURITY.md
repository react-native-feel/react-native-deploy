# Security policy

React Native Deploy handles signing material: App Store Connect API keys, iOS distribution
certificates, provisioning profiles and Android keystores. Please report anything that could
expose them, or let someone install or upload builds they shouldn't, privately.

## Reporting a vulnerability

Use GitHub's private reporting:
[Report a vulnerability](https://github.com/react-native-feel/react-native-deploy/security/advisories/new).
Don't open a public issue or PR for it.

Include what is affected (`rnd` CLI, the build workflow template, the dashboard, or the install
service), how to reproduce it, and the impact you see. You'll get an acknowledgement within a few
days and a fix or a plan before anything is disclosed.

## Supported versions

Only the latest release of `@react-native-feel/deploy` on npm receives fixes. Workflows
generated by `rnd build:configure` are fixed by re-running it after upgrading.

## How secrets are handled

- Signing assets are stored as GitHub repository secrets, sealed client-side with the repo's
  public key; they are never sent anywhere else by `rnd`.
- On the runner, iOS assets go into a throwaway keychain that an `always()` step deletes.
- The GitHub token from `rnd login` is stored at `~/.eas-gh/auth.json` with mode `0600`.
- The install service's upload and device APIs require a bearer token (`UPLOAD_TOKEN`) set as a
  Cloudflare secret; install pages are public by design but addressed by unguessable ids.
